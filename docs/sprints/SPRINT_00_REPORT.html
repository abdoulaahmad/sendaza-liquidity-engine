Sprint 0: Repository Foundation

How SLE became a runnable engineering workspace

Partially delivered

Honest status: the repository and application skeleton were delivered. Docker, persisted worker heartbeat, and complete Railway API/worker deployment were deferred.

Before and Goal

SLE began as design documents. There was no application to compile, test, or run. Sprint 0 created the workshop before building the machine: one repository, one package manager, API and worker processes, shared packages, tests, and repeatable commands.

What Was Built

PartPurpose
apps/apiReceives private Sendaza Core requests.
apps/workerRuns scheduled and queued jobs.
packages/*Separates domain, database, contracts, configuration, observability, and testing.
pnpm, NestJS, TypeScriptProvide one reproducible, modular, strictly typed workspace.

Flow

pnpm command -> shared build -> API process
                             -> worker process

System Link

Later pricing and withdrawal calls enter through the API. Rate refresh, event delivery, fee refresh, and reconciliation run in the worker. Shared domain packages keep financial rules independent of frameworks and provider SDKs.

Rules and Evidence

  • Node 24 and pinned pnpm are the toolchain.
  • The MVP is one modular codebase with separate processes.
  • Secrets stay outside source control.
  • Money never uses floating-point arithmetic.

The scaffold compiled and tests ran locally. GitHub Actions was added later, but the account runner was externally blocked. Railway PostgreSQL was also created later. Docker evidence was unavailable on this PC.

Glossary

Workspace: related apps managed together. API: an interface another program calls. Worker: a background process. Dependency injection: supplying a component's dependencies from outside.
