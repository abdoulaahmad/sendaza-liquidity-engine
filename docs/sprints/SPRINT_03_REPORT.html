The worker resolves server-controlled providers. Decimal strings are validated and stored. Ordered multiply or divide legs use decimal.js, normalize once with half-even rounding, run guards, and commit the snapshot plus evidence in one PostgreSQL transaction.

Safety Rules

  • No floating point rate math.
  • Missing, stale, deviating, sequence-gap, or depegged evidence rejects pricing.
  • Accepted snapshots require one matching observation per leg.
  • Evidence is immutable.
  • Expired leases can be reclaimed after a worker crash.
  • Provider timeouts never erase stored evidence.

Limitations and Risks

  • No production route or refresh job is active.
  • Real funds require independent redundant sources.
  • Coinbase reference data is not guaranteed liquidity or an executable price.
  • Quotes, custody, treasury, network fees, withdrawals, finality, and reconciliation remain later work.
  • The Railway project currently contains PostgreSQL; API and worker deployment is deferred.

Next Sprint

Sprint 4 builds immutable executable quotes from accepted snapshots. It adds spreads, fixed or percentage purchase fees, exact debit and asset amounts, limits, expiry, idempotency, and stable Sendaza-facing errors.

Glossary

Observation: one price fact. Leg: one route step. Cross-rate: a rate through intermediate pairs. Snapshot: a result linked to evidence. Depeg: movement outside a reference band. Basis point: 0.01 percent. Lease: temporary job ownership. Idempotent: repeatable without a second effect.
