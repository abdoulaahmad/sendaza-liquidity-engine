Sprint 5: Fireblocks Treasury Synchronization

Turning custody and blockchain evidence into safe network-scoped inventory

Delivered 2 September 2026

Final status: The implementation, migrations, tests, worker, and documentation are delivered. Both isolated test and Railway production databases have all 10 migrations. No provider or wallet was activated. A live funded Fireblocks sandbox demonstration remains externally pending because this environment has no sandbox credential or funded vault.

Connection to Earlier Sprints

Sprint 1 created separate assets, networks, and asset-network mappings. Sprint 2 supplied durable jobs and operational reliability patterns. Sprint 3 made pricing evidence reproducible. Sprint 4 created quotes but deliberately did not promise inventory. Sprint 5 now establishes verified treasury evidence that Sprint 6 will lock when it creates a purchase reservation.

What Was Built

  • treasury.ts defines provider boundaries, exact inventory calculation, fail-closed evidence states, and retryable batch orchestration.
  • prisma-treasury.repository.ts selects enabled wallets, atomically stores snapshots and current state, and leases jobs with SKIP LOCKED.
  • fireblocks-custody.provider.ts signs read-only Fireblocks requests with short-lived RS256 JWTs and returns decimal-string evidence.
  • evm-chain-balance.provider.ts independently checks native and ERC-20 balances using public JSON-RPC methods.
  • The migration adds custody providers, wallets, immutable snapshots, current inventory, sync jobs, and forward-only funding intents.

Concrete Example

Suppose a Sepolia ETH wallet has 2 ETH controlled and Fireblocks says 1.8 ETH is available. A 0.10 ETH safety buffer and 0.05 ETH gas reserve leave 1.65 ETH sellable. If the chain adapter reports even one atomic unit less than the provider total, status becomes MISMATCH and sellable becomes zero. ETH on Sepolia cannot support ETH or USDT on any other network.

Financial and Security Rules

  • All provider decimal strings convert exactly to atomic bigint; excess precision is rejected.
  • Stale or conflicting evidence cannot support a purchase.
  • Provider available balance cannot exceed controlled balance.
  • Important wallets cannot publish unverified sellable inventory.
  • Snapshots are immutable and PostgreSQL independently checks inventory arithmetic.
  • SLE stores public addresses and provider identifiers, never wallet private keys or seed phrases.
  • The Fireblocks RSA API private key authenticates SLE only and stays in encrypted deployment configuration.

Limitations and Next Dependency

The repository contains no populated credentials, live provider record, enabled wallet, RPC secret, or faucet funding. The initial independent chain adapter supports EVM native assets and ERC-20 tokens; other network families need their own adapters before activation. Sprint 6 must lock the current asset-network inventory row, reject expired or unsafe evidence, and reserve inventory atomically without using another network.

How to Complete the Live Demo

An authorized operator must create a Fireblocks Developer Sandbox API user, store its API key and RSA API private key in Railway secrets, configure an HTTPS Sepolia RPC URL, register the exact Fireblocks vault ID, provider asset ID, and public address in a disabled wallet row, fund it with testnet assets, verify provider and chain agreement, then enable the wallet and its sync job through a reviewed migration or administration procedure.

Glossary

MPC: signing in which no single system holds a complete treasury key. Vault: a Fireblocks account containing asset wallets. Controlled: total assets reported for the configured wallet. Unallocated: provider-available assets before SLE buffers and reservations. Sellable: inventory allowed to support a new reservation. Funding intent: an auditable expectation of manual treasury funding, not a command to move funds.
