What Was Built

  • fireblocks-webhook.controller.ts and fireblocks-webhook.verifier.ts authenticate Fireblocks Webhooks V2 over the exact raw body with RS512.
  • prisma-custody-webhook-inbox.repository.ts stores verified events before acknowledgement and deduplicates provider event IDs.
  • withdrawal-finality.ts defines one evidence and processing contract shared by webhooks and polling.
  • prisma-withdrawal-finality.repository.ts claims work with leases, appends evidence, advances state, and writes the outbox event atomically.
  • fireblocks-custody-transfer.provider.ts polls a transfer by Fireblocks ID when a webhook is missing.
  • evm-chain-finality.provider.ts independently checks the receipt, network route, token/native asset, destination, exact atomic amount, execution result, and confirmations.
  • Migration 20260907193000_withdrawal_webhooks_finality introduced inbox, attempt, hash, observation, and polling-job tables. Migration 20260908160000_finality_match_evidence added explicit chain-match evidence.

Replacement Flow

For an EVM replace-by-fee transaction, Fireblocks supplies replacedTxHash. SLE links it to the current attempt, keeps the original attempt and hash immutable, and creates a new current attempt only when the new provider ID, external transaction ID, new hash, and old hash are complete. Delayed events for the old attempt remain evidence but cannot become authoritative again. Incomplete or conflicting replacement evidence enters reconciliation.

System Boundary

Sendaza still owns customer authentication, the crypto and fee lock, ledger posting, customer history, and the customer interface. SLE owns custody evidence, blockchain evidence, and withdrawal state. Fireblocks holds MPC signing shares; SLE never receives a treasury private key. The RPC adapter is read-only and cannot sign or move funds.

Rules Protected

  • A provider timeout or missing webhook is uncertainty, not failure.
  • Fireblocks COMPLETED is not confirmation when independent verification is required.
  • A broadcast transaction is never treated as final settlement.
  • Chain confirmation requires positive execution, network, asset, destination, amount, and threshold matches.
  • Post-submission provider failure never automatically releases the Sendaza lock.
  • Events, transaction attempts, hashes, and observations are immutable or append-only.
  • State transition and outbound Sendaza event commit in one PostgreSQL transaction.
  • Workers use bounded leases and FOR UPDATE SKIP LOCKED, so a crash can be retried safely.
  • Post-confirmation conflicting evidence emits an incident event and does not rewrite completed history.

Glossary

Finality: confidence that a blockchain transaction will not be reversed. Receipt: chain evidence showing whether an EVM transaction executed and which block contains it. Confirmation: a block added after or including the transaction block. RBF: replace by fee, where a stuck EVM transaction is replaced using the same nonce and a higher fee. Webhook: a provider callback. Polling: SLE asking the provider periodically when callbacks are absent. Lease: a time-limited database claim that another worker may recover after expiry. Outbox: committed events waiting for reliable delivery to Sendaza.
